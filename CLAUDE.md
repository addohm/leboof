# CLAUDE.md

Orientation for Claude working on leboof. Read this first.

## What this is

Leboof is a WoW: Forever addon (Interface 16001: the modern retail client with the Midnight
"secret values" addon API, running Classic level-60 content). It shows the player's own buffs in
combat by handing spell IDs to Blizzard's aura containers (`Blizzard_AuraContainer`,
`CustomAuraContainerTemplate`), which fill the buttons securely. The display never reads aura data;
only the Add-a-buff list reads the player's buffs, out of combat.
The remote is `addohm/leboof` on GitHub (`origin`, branch `main`).

Scope agreed on 2026-11-07: the player's own buffs only; a separate addon from periodic (the
owner's aura-suite plan). Out-of-game approaches (screen or memory reading, pixel encoding) are
off the table.

## Layout

- `Leboof/`: the addon (what players copy into `Interface\AddOns`). `Leboof.toc` sets the load
  order and holds `## Version`, the only version source.
  - `Build.lua`: build stamp, empty in the repo; the install script writes the commit into it.
  - `Data.lua`: GENERATED by `tools/gen_data.py`. Never edit by hand.
  - `Buffs.lua`: the catalogue: each buff's key, spell names, default mode per class, warn time.
  - `Core.lua`: the defaults (`ns.DEFAULTS`), modes, events, `/leboof`.
  - `Custom.lua`: buffs the player adds (`ns.db.custom`), `ns.Entries()`, reading the player's buffs
    out of combat, learning other IDs of added buffs by name.
  - `Profiles.lua`: profiles. `LeboofDB.profiles[name]` holds every setting (modes, size, gap,
    icon position, `window`, `minimap`); `LeboofDB.chars["Name - Realm"]` is the profile each
    character uses; `ns.db` is the one in use. New, switch, copy, rename, delete, reset. It also
    moves 0.1.0's settings (per-character `LeboofCharDB`, account `LeboofDB.window/.minimap`)
    into the character's profile once, then clears `LeboofCharDB`.
  - `Display.lua`: the anchor, the containers, the keep-row placeholders, the up-row groups.
  - `UI/Widgets.lua`: option rows (check, arrow picker, button, heading, text) and the scrolling
    `UI.Stack`, in Nothing Wasted's style. `UI/Window.lua`: the options window (tabs, Defaults,
    resize grip; pages register with `ns.Window.AddPage`). `UI/Pages.lua`: the Buffs, Layout and
    General tabs. `UI/Minimap.lua`: the minimap button and the addon compartment entry.
  - `Media/Icon.tga`: the in-game icon (TOC `IconTexture`: AddOns list, addon compartment),
    128 px 32-bit TGA, drawn by `art/make_logo.py`. Never edit by hand.
- `art/`: `make_logo.py` (Pillow; run `python3 art/make_logo.py`) and the icon PNGs it draws
  (512, 256, 128 px) for listings.
- `tools/gen_data.py`: fetches Forever's SpellName table from wago.tools and writes `Data.lua`.
- `tools/install_forever.cmd`: pulls, copies the addon into the Windows client, stamps the build
  and packs `Leboof-<version>.zip` on the desktop. Keep it CRLF (`.gitattributes`).
- `tests/`: `wowmock.lua` (a fake client, including aura containers that assert like Blizzard's),
  `smoke.lua` (scenarios), `run_tests.py`.
- `TESTING.md`: what to check in game, and what's been confirmed.
- `.scratch/`: git-ignored downloads (Blizzard UI source, the wago.tools CSV).

## Workflow

1. Start from the latest: pull before changing anything.
2. Make the change with tests.
3. **Update the docs in the same commit.** Every change updates the docs it
   affects:
   - README.md: setup and usage
   - CHANGELOG.md: an entry under *Unreleased*
   - DEPLOY.md: when deploying or running it live changes
   - SECURITY.md: when secrets, access or permissions change
   - ROADMAP.md: when something on it is done, or new plans are made
   - TESTING.md: what needs checking in game, and results the owner reports
   - this file: when the layout, workflow or conventions change
4. Run the checks: `.venv/bin/python tests/run_tests.py` (set up with
   `python3 -m venv .venv && .venv/bin/pip install lupa`). Then commit and push, and say
   "Pushed: <commit>" so the owner can run the install script.

## Conventions

- **The display never reads aura data.** In combat it's secret (in instances even the aura IDs
  are refused). Displays go through the aura containers. The one reader is `ns.ReadBuffs()` in
  `Custom.lua`: the player's buffs, out of combat only, in `pcall`, skipping secret values, for
  adding buffs and learning their other IDs by name.
- **Only buffs on the player can be tracked** (the containers match spell IDs only for helpful
  auras on assistable units). Added buffs come from `ns.ReadBuffs()`, never typed names or IDs.
- Loop over buffs with `ns.Entries()` (built-in, then the profile's added ones) and look them up
  with `ns.Entry(key)`; `ns.Catalogue` and `ns.byKey` are the built-in ones only.
- **Touch the containers only out of combat.** Their buttons are closed to addons while auras are
  secret (`DenyTaintedAccessWhenAurasAreSecret`). Changes go through `ns.Refresh()`, which waits
  for `PLAYER_REGEN_ENABLED`. Button parts are built in `initializeFrame`.
- Container slots and groups can't be removed: create each once, then enable, disable or
  re-filter it.
- Check API against Blizzard's UI source, `forever` branch:
  https://github.com/Gethe/wow-ui-source/tree/forever. Prefer `C_*` functions; many old globals
  are gone.
- Spell IDs come from `Data.lua`, by name. Add a buff by adding its names to `Buffs.lua` and
  running `tools/gen_data.py`; it reports names with no IDs.
- Lua 5.1, no libraries (Ace, LibStub). Every file starts `local _, ns = ...`; shared state goes
  on `ns`. Globals: `LeboofCharDB`, `LeboofDB`, `LeboofAnchor`, `LeboofFrame`,
  `LeboofMinimapButton`, `SLASH_LEBOOF1/2`,
  `Leboof_OnAddonCompartmentClick` (the tests enforce this). `LeboofCharDB` is only read
  for the move to profiles; new settings go in a profile (`ns.DEFAULTS`), never there.
- Display only: never automate anything or call protected functions.
- No code copied from other addons.

## Don't

- Commit secrets (`.env`, keys, tokens), `.venv/` or `.scratch/`.
