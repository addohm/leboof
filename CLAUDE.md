# CLAUDE.md

Orientation for Claude working on leboof. Read this first.

## What this is

Leboof is a WoW: Forever addon (Interface 16001: the modern retail client with the Midnight
"secret values" addon API, running Classic level-60 content). It shows the player's own buffs in
combat by handing spell IDs to Blizzard's aura containers (`Blizzard_AuraContainer`,
`CustomAuraContainerTemplate`), which fill the buttons securely. The display never reads aura data;
only the Add-a-buff list reads the player's buffs, out of combat.
The remote is `addohm/leboof` on GitHub (`origin`, branch `main`).

Scope agreed on 2026-11-07: the player's own buffs only; a separate addon from periodic (the
owner's aura-suite plan). Out-of-game approaches (screen or memory reading, pixel encoding) are
off the table.

## Layout

- `Leboof/`: the addon (what players copy into `Interface\AddOns`). `Leboof.toc` sets the load
  order and holds `## Version`, the only version source.
  - `Build.lua`: build stamp, empty in the repo; the install script writes the commit into it.
  - `Data.lua`: GENERATED by `tools/gen_data.py`. Never edit by hand.
  - `Buffs.lua`: the catalogue: each buff's key, spell names, default mode per class, warn time.
  - `Core.lua`: the defaults (`ns.DEFAULTS`), modes, events, `/leboof`.
  - `Custom.lua`: buffs the player adds (`ns.db.custom`), `ns.Entries()`, reading the player's buffs
    out of combat, learning other IDs of added buffs by name.
  - `Glow.lua`: the glow styles, built from textures and Alpha/Translation/Rotation/FlipBook
    animations only (`Glow.Build`); `Glow.Show` keeps one active on our own frames.
  - `Effects.lua`: glow, icon-look and sound settings (`ns.db.effects` defaults, `ns.db.fx[key]` a
    buff's own; `ns.Fx.Get(e, field)` resolves them), sounds out of combat (from `ns.ReadBuffs()`),
    the warning on entering combat, the running-out sound (out of combat from the real timer, in
    combat timed from your own casts: `UNIT_SPELLCAST_SUCCEEDED`, durations learned per character
    in `LeboofDB.durations`; `castPlayed` stops a second play after combat), the warning time
    (`Fx.Warn(e)`: the player's choice or "auto" = the buff's built-in `warn`; it also sets the
    red text, so it's part of a button's key), and the Cooldown Manager check.
  - `SoundLog.lua`: `/leboof soundlog`: hooks PlaySound, PlaySoundFile,
    C_Sound.PlaySoundWithOptions (Cooldown Manager alerts) and C_VoiceChat.SpeakText with
    `hooksecurefunc`, names the calling addon from `debugstack`, keeps the last 300 entries in
    `LeboofDB.soundlog`. `ns.Fx.Play(name, why)` passes Leboof's reason. Global frame `LeboofSoundLog`.
  - `Profiles.lua`: profiles. `LeboofDB.profiles[name]` holds every setting (modes, size, gap,
    icon position, `window`, `minimap`); `LeboofDB.chars["First Last"]` (`P.CharKey`: UnitName's second value is the surname on
    Forever; no realm) is the profile each
    character uses; `ns.db` is the one in use. New, switch, copy, rename, delete, reset. It also
    moves 0.1.0's settings (per-character `LeboofCharDB`, account `LeboofDB.window/.minimap`)
    into the character's profile once, then clears `LeboofCharDB`.
  - `Display.lua`: the anchor, the containers, the up-row groups, the
    buttons' parts (`ButtonStyler`: the face, the timer, the glows), the timed warning glow
    (`AddTimedGlow`) and the presence frames for the expired glow and "only when missing"
    (`Presence`, `PlaceExpired`).
  - `UI/Widgets.lua`: option rows (check, arrow picker, button, heading, text) and the scrolling
    `UI.Stack`, in Nothing Wasted's style. `UI/Window.lua`: the options window (tabs, Defaults,
    resize grip; pages register with `ns.Window.AddPage`). `UI/Pages.lua`: the Buffs, Layout,
    Effects, General and Profiles tabs, and a buff's ⚙ menu (`ns.BuildFxMenu`). `UI/Minimap.lua`: the minimap button and the addon compartment entry.
  - `Media/Icon.tga`: the in-game icon (TOC `IconTexture`: AddOns list, addon compartment),
    128 px 32-bit TGA, drawn by `art/make_logo.py`. Never edit by hand.
- `art/`: `make_logo.py` (Pillow; Inter for the banner via LEBOOF_FONT_BOLD/SEMI) and what it
  draws: the icon PNGs (512, 400 for the listing avatar, 256, 128) and `leboof-banner.png`
  (1600x500).
- `LISTING.md`: the CurseForge / Wago page text (basics, summary, description, screenshot list,
  release notes). Keep its feature list in step with README.md.
- `release/`: `Leboof-<version>.zip` release packages, built by `tools/make_release.py` from the
  committed `Leboof/` folder; committed with each release.
- `tools/gen_data.py`: fetches Forever's SpellName table from wago.tools and writes `Data.lua`.
- `tools/install_forever.cmd`: pulls, copies the addon into the Windows client, stamps the build
  and packs `Leboof-<version>.zip` on the desktop. Keep it CRLF (`.gitattributes`).
- `tests/`: `wowmock.lua` (a fake client, including aura containers that assert like Blizzard's),
  `smoke.lua` (scenarios), `run_tests.py`.
- `TESTING.md`: what to check in game, and what's been confirmed.
- `.scratch/`: git-ignored downloads (Blizzard UI source, the wago.tools CSV).

## Workflow

1. Start from the latest: pull before changing anything.
2. Make the change with tests.
3. **Update the docs in the same commit.** Every change updates the docs it
   affects:
   - README.md: setup and usage
   - CHANGELOG.md: an entry under *Unreleased*
   - DEPLOY.md: when deploying or running it live changes
   - SECURITY.md: when secrets, access or permissions change
   - ROADMAP.md: when something on it is done, or new plans are made
   - TESTING.md: what needs checking in game, and results the owner reports
   - this file: when the layout, workflow or conventions change
4. Run the checks: `.venv/bin/python tests/run_tests.py` (set up with
   `python3 -m venv .venv && .venv/bin/pip install lupa`). Then commit and push, and say
   "Pushed: <commit>" so the owner can run the install script.

## Conventions

- **The display never reads aura data.** In combat it's secret (in instances even the aura IDs
  are refused). Displays go through the aura containers. The one reader is `ns.ReadBuffs()` in
  `Custom.lua`: the player's buffs, out of combat only, in `pcall`, skipping secret values, for
  adding buffs and learning their other IDs by name.
- **Only buffs on the player can be tracked** (the containers match spell IDs only for helpful
  auras on assistable units). Added buffs come from `ns.ReadBuffs()`, never typed names or IDs.
- Loop over buffs with `ns.Entries()` (built-in, then the profile's added ones) and look them up
  with `ns.Entry(key)`; `ns.Catalogue` and `ns.byKey` are the built-in ones only.
- **Touch the containers only out of combat.** Their buttons are closed to addons while auras are
  secret (`DenyTaintedAccessWhenAurasAreSecret`). Changes go through `ns.Refresh()`, which waits
  for `PLAYER_REGEN_ENABLED`. Button parts are built in `initializeFrame`.
- Container slots and groups can't be removed: create each once, then enable, disable or
  re-filter it. A button's warning glow is fixed when the game creates it (`initializeFrame`), so
  slots, groups and enchant containers are keyed by buff (or warn time) *and* glow
  (`"<key>/<style>:<colour>:<size>"`); changing a buff's glow switches to another button.
- **The keep row's warning glow is timed by layout too.** The game's own warning-glow hook (the
  pandemic window) only exists for auras with a refresh window, which most buffs lack. So each
  keep-row button gets an invisible StatusBar the game drives from the time left
  (`SetDurationBar`, RemainingTime; range 0..duration), k px per second wide, placed so its fill's
  end crosses the glow's area between warn + T and warn. The glow sits in a window from the fill's
  end to the bar's end (`DisableUntrustedLayoutScriptsTemplate`, clips), inside a frame clipped to
  the glow's area. It needs the buff's duration (`Fx.Duration`, learned out of combat; a new one
  rebuilds the buttons), so the slot key includes it; without one, and in the second row, the
  pandemic glow is used. `Display.lua`: `AddTimedGlow`.
- **The expired glow is hidden by layout, not by reading anything.** Each keep-row buff has its
  own "presence" container holding only that buff (invisible 1 px buttons, element width = the
  glow's span + 1). Empty, a container is 1 px wide; with the buff, span + 1. The glow's clipping
  frame (made with `DisableUntrustedLayoutScriptsTemplate`, which Blizzard requires for frames
  anchored to a container) runs from the container's right edge to a fixed point, so it's full
  size while the buff is missing and zero while it's up. The game does the sizing with secret
  values; Leboof never learns it. `Display.lua`: `Presence`, `PlaceExpired`. The red copy sits in
  the same frame (`PlaceExpired(e, x, size, true)`), for "keep up" and "only when missing" buffs
  alike, so it's gone while the buff is up rather than covered by Blizzard's button (a see-through
  icon would show its red). "Only when missing" buffs (mode `missing`) have no Blizzard button.
- A Blizzard button's look (border, icon, timer, stacks) is on a "face" child frame, so the
  opacity and grey while up (`upAlpha`, `upGrey`, part of the button's key) leave the glows, on
  frames above it, at full strength.
- **Keep it simple:** icons appear and disappear, with a warning glow and an expired glow, and
  nothing else animates (the owner, 2026-11-08: no growing, shrinking or fading). The keep row's
  warning glow is timed by the bar above; elsewhere it goes through the button's own
  `AddPandemicRegion` / `AddPandemicActiveAnimation`, and the game shows it. Nothing may detect a button showing (no scripts on its children); in combat only casts and
  Blizzard's Cooldown Manager can make a sound.
- Check API against Blizzard's UI source, `forever` branch:
  https://github.com/Gethe/wow-ui-source/tree/forever. Prefer `C_*` functions; many old globals
  are gone.
- **Check a buff is in Forever before adding it.** Forever's spell data (wago.tools `wowf`) also
  holds Season of Discovery runes and spells that aren't in the game, so a name with IDs proves
  nothing. Use Forever sources: the wiki's `<Class>_abilities_(Forever)` pages, Blizzard's class
  deep dives, Wowhead's Forever database. World buffs and racials get a `note` (shown in tooltips)
  saying where they come from, and whether that's confirmed.
- Spell IDs come from `Data.lua`, by name. Add a buff by adding its names to `Buffs.lua` and
  running `tools/gen_data.py`; it reports names with no IDs.
- Lua 5.1, no libraries (Ace, LibStub). Every file starts `local _, ns = ...`; shared state goes
  on `ns`. Globals: `LeboofCharDB`, `LeboofDB`, `LeboofAnchor`, `LeboofFrame`,
  `LeboofMinimapButton`, `LeboofSoundLog`, `SLASH_LEBOOF1/2`,
  `Leboof_OnAddonCompartmentClick` (the tests enforce this). `LeboofCharDB` is only read
  for the move to profiles; new settings go in a profile (`ns.DEFAULTS`), never there.
- Display only: never automate anything or call protected functions.
- No code copied from other addons.

## Don't

- Commit secrets (`.env`, keys, tokens), `.venv/` or `.scratch/`.
